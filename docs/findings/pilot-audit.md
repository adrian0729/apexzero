## Setup

- **Checkpoints:** 13 DR-pilot checkpoints, 10.0M, 12.2M, 14.9M, 18.2M, 22.2M, 27.1M, 33.1M, 40.5M, 49.4M, 60.3M, 73.7M, 90.0M, 109.9M (single seed). Skipped: 000134140317 (not audited yet: --report-only), 000163792745 (not audited yet: --report-only), 000200000000 (not audited yet: --report-only).
- **Levels:** the first 150 A_DR levels (`make_levels(PRNGKey(2026), 'a_dr')`), grammar fitted on R-dev only. No lockbox (R-test) circuit is used anywhere.
- **Windows:** 32 stochastic 1,200-step windows per level and checkpoint, with 1% observation noise; one chunk phase per window drawn from U{0..127} (seed 2026); mode F scoring (window end terminal), λ = 0.95 headline. The same random draws are reused at every checkpoint (common random numbers).
- **Window roles (plan 2.2):** high-budget scores use the odd windows (1, 3, ..., 31), the target the even windows; operational scores use windows 1-4 and their target windows 5-32.
- **Target:** J^π = mean discounted return over the target windows; J_best = max over checkpoints of that mean (from the target windows only, so scores and labels share no window noise); Reg = J_best − J^π, Reg_norm = Reg / J_best. J_best is a lower bound on the env's optimal expected return (every window, crashed or not, is a trajectory of the env), not necessarily on the J\*_20 label.
- **d_QSS** (S2 success threshold and the geometric baseline): the centreline distance the QSS point mass of the level's own car (context and hidden grip) covers in 60 s on the minimum-curvature line inside the corridor (edge margin 1 m, as the env's off-track test), starting from x0 (n = 0, 0.8·v_QSS(0)); `audit.qss_distance`. It replaces the centreline-curvature definition, which completed windows beat by up to 23% (see *d_QSS check*).
- **Phase:** window completion rate over all windows of the audited levels (<50% early, 50-90% mid, ≥90% late).
- **Statistics:** percentile bootstrap over levels, 1000 resamples shared by all scores and all checkpoints (Δ columns are paired). One seed, so no seed-level variance is included: CIs are too narrow for the plan's two-way bootstrap.
- **Compute:** rollouts + window statistics 28.4 min wall, 55.0 min CPU in total (nice 15, on a machine shared with training runs). Cached statistics from before the cache recorded checkpoint hashes, accepted because each checkpoint file predates its cache: 13 checkpoints.

Baselines: *agent-only* = −J^π on the score windows; *J_best, score windows* = the policy-agnostic optimum baseline (recomputed from the score windows, in the role J\*_20 will play); *geometric* = −d_QSS (shorter = slower, more technical strip); *random*. *Best baseline* = the best of agent-only, J_best and geometric within each bootstrap resample. The *proxy regret, score windows (reference)* row is the oracle-operational reference, J_best − J^π on the score windows: a reference, not a ceiling.

Caveats on the reliability numbers: Spearman-Brown is applied only on the raw scale, where it is an identity for a mean of i.i.d. windows. ## Per-checkpoint tables (high budget)

ρ = Spearman against Reg and against Reg/J_best; RC@10% = share of total regret in the score's top 10% of levels (random = k/L = 0.10); lift = (RC − k/L) / (RC_oracle − k/L), so random = 0 and the regret-sorted oracle = 1. The oracle's own share (in each heading) depends on how concentrated regret is: early it is spread almost evenly and the oracle captures little more than k/L, so the raw share barely moves; late, the proxy's exact zeros concentrate it on a few levels. Dividing by the oracle share alone would rate a random score close to 1 early on; the lift does not. P@10% = overlap of the top 10% sets; a, b = standardised loadings of rank(S) on rank(J_best) and rank(J^π) (faithful: a > 0, b < 0); Δρ = ρ minus the agent-only baseline's ρ, paired; Δρ best = ρ minus the best baseline's ρ per resample, paired; ρ* = ρ disattenuated by the Spearman split-half reliabilities of score and target (an approximation; it can exceed 1 in magnitude when those reliabilities are small).

## Limits of this pilot

- **Degenerate late.** J_best is attained by the best checkpoint on each level, so that checkpoint's regret is exactly 0 there (see *attains J_best*). As training improves, the newest checkpoints' labels collapse toward 0; checkpoints that attain J_best on 10% of levels or more are reported but not graded. The earlier checkpoints are graded against what this run later reached, which is regret relative to the run, not to the optimum.
- **Collinear loadings.** J_best is close to the late J^π, so corr(J_best, J^π) is high and the two-loading coefficients are poorly identified; with J\*_20 (a property of the level, not of the run) the regression becomes meaningful.
- **Lower bound, not the optimum.** Reg ≥ 0 by construction and understates true regret everywhere the run never got close to J\*. Normalised regret divides by a run-dependent number.
- **Pilot scale.** One seed, mid-phase checkpoints only (no late phase yet unless the table says so), 150 levels instead of 1,000 A_DR + 300 A_tail + 100 A_OOD, 32 windows (64 only in the sub-pilot) without the adaptive raise, no Holm correction, no seed-level bootstrap.
- **d_QSS** is a point-mass reference on a minimum-curvature line, not a minimum-time trajectory of the full model; the *d_QSS check* table says how often the agent beats it. The start deficit (0.8·v_QSS(0)) is now included.

What carries over unchanged to the real audit: the window roles and cross-fitting, the metrics and their tie handling, the paired bootstrap (including the best-baseline rule), the split-half reliability on both scales, the empirical window budgets, d_QSS, and the units check.
